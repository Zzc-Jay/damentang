# 《大门塘》游戏需求文档

> 版本：v0.1 | 日期：2026-05-11 | 状态：初稿

---

## 一、项目概述

### 1.1 项目名称
**大门塘（Damentang）**

### 1.2 项目定位
一款受《锈湖》（Rusty Lake）系列启发的暗黑风格点触式解谜游戏。玩家通过探索场景、收集道具、破解谜题来推进故事，逐步揭开"大门塘"背后隐藏的秘密。

### 1.3 目标平台
- **首发**：PC（Windows / macOS）、移动端（iOS / Android）
- **可选**：Web（HTML5）

### 1.4 目标用户
- 解谜游戏爱好者，年龄 16+
- 喜欢暗黑、悬疑、超现实主义风格的玩家
- 《锈湖》《未上锁的房间》《致命框架》系列的受众

### 1.5 核心体验
- **沉浸感**：通过怪异诡谲的氛围、音效和画面，让玩家感到不安与好奇并存的情绪
- **成就感**：每个谜题都提供"Aha!"时刻，看似无关的道具最终串联在一起
- **叙事驱动**：谜题服务于故事，揭开真相的过程就是解谜的过程

## 二、故事背景

### 2.1 世界观
故事发生在一个被遗忘的南方水乡——大门塘。这里曾经是一个繁荣的家族聚居地，围绕着"塘"而建。某一年，塘水突然变黑，家族成员接连失踪，整个地方逐渐荒废。

### 2.2 主线剧情（草案）
玩家扮演一名收到远方亲戚遗书的继承人，回到大门塘处理遗产。抵达后发现整个宅院空无一人，但处处残留着他人刚刚离开的痕迹。通过破解一个个房间中的谜题，玩家将逐渐拼凑出家族隐藏的秘密——塘底封存着某种不可名状的存在，而家族的每一代都在用某种仪式维持封印。遗书并非邀请，而是一份传承契约。

### 2.3 叙事结构
- **明线**：探索宅院 → 破解谜题 → 收集记忆碎片 → 了解家族历史
- **暗线**：通过信件、日记、照片等碎片化叙事，还原"塘"的真相
- **结局**：设计 2-3 个结局（取决于关键选择/隐藏谜题是否完成）

### 2.4 关键角色（草案）
| 角色 | 关系 | 简介 |
|------|------|------|
| 主角 | 继承人 | 多年未归的家族后人，沉默寡言 |
| 祖父 | 最后一位守门人 | 坚守祖宅直到失踪，留下了关键线索 |
| 姑母 | 叛逃者 | 唯一试图逃离家族命运的人，留下警告信 |
| "塘底之物" | 不可名状 | 被封印的存在，通过梦境影响家族成员 |

## 三、核心玩法

### 3.1 游戏循环
```
进入新场景 → 观察环境 → 收集道具 → 破解谜题 → 解锁新区域 → 推进剧情
```

### 3.2 基础交互
- **点击**：移动/调查物品/拾取道具
- **拖拽**：组合道具/使用道具
- **长按**：查看道具详情
- **双指捏合**（移动端）：缩放场景

### 3.3 背包系统
- 底部常驻背包栏，存放收集的道具
- 道具可**组合**（如：火柴 + 蜡烛 = 点燃的蜡烛）
- 道具可**拆解**（在特定场景下）
- 道具带有简介文字，暗含线索

### 3.4 场景系统
- 每个"房间"是一个独立场景（2D 静态画面 + 可交互区域）
- 场景支持**左右滑动/点击箭头**切换视角
- 部分场景有**前后景深**，需要进入子场景
- 隐藏交互区域（彩蛋）：点击某些看似无意义的区域触发隐藏内容

### 3.5 谜题类型

| 类型 | 描述 | 示例 |
|------|------|------|
| 道具组合 | 收集多个道具组合使用 | 钥匙 + 钳子 → 修复的钥匙 |
| 密码/符号 | 观察环境中隐藏的符号或数字 | 墙上的画对应箱子密码 |
| 顺序逻辑 | 按照特定顺序触发机关 | 按家族辈分顺序拉动雕像 |
| 拼图/拼接 | 将碎片拼成完整图案 | 撕碎的照片、地图碎片 |
| 声音线索 | 通过声音判断操作是否正确 | 钢琴按正确顺序发出旋律 |
| 时间谜题 | 调节钟表、日历等时间装置 | 将钟调到特定时间触发暗门 |
| 光线/影子 | 利用光源照亮或投影 | 调整镜子反射光线 |
| 化学/炼金 | 混合不同材料产生反应 | 调配药水、颜料 |

## 四、美术风格

### 4.1 总体方向
- **暗黑超现实主义**：在写实基础上进行扭曲和夸张
- **手绘质感**：类似油画/水彩的笔触，带手绘线稿感
- **复古色调**：以墨绿、暗棕、锈红、灰蓝为主色调
- **怪异感**：比例略微失调的人偶、不自然的阴影、重复的几何符号

### 4.2 场景设计
- 2D 静态场景，分辨率基准 1920×1080
- 场景划分清晰的**可交互热区**
- 关键道具在画面中突出但不突兀（通过光影或色彩引导）
- 背景细节蕴含叙事信息（墙上的照片、桌上的信件等）

### 4.3 UI风格
- 极简HUD，尽量减少屏幕上的UI元素
- 背包以图标形式排列在底部
- 文字提示使用手写体/仿古字体
- 过场使用墨水晕染转场效果

### 4.4 关键场景（第一章节 v0.8）
1. **村口**（入口）：杨梅坑村口，大门塘漆黑如墨，废弃的船坞
2. **祠堂**：曾氏宗祠，三房牌位，三兄弟木匾，香炉尚有余温
3. **书房**：满墙的三房手稿和研究笔记，三房排序木格机关
4. **卧室**：收拾整齐却布满灰尘，枕头下有姑母的信，木根村长残影
5. **暗道**：通往塘底的漆黑通道，铜镜反射光线谜题
6. **封印之间**（终章）：水下密室，中央封印，最终抉择

## 五、音频设计

### 5.1 音乐
- 氛围音乐为主，不使用强旋律（避免喧宾夺主）
- 每个场景独立配乐，随解谜进度变化（如：触发关键机关后音乐变奏）
- 主题旋律仅在关键剧情节点完整出现
- 使用真实乐器采样：大提琴、钢琴、水滴、风铃

### 5.2 音效
- 所有交互均有点击/拾取/放置反馈音效
- 环境音效：水声、风声、木板吱呀、远处的钟声
- 机关音效：齿轮转动、锁簧弹开、石门滑动
- 强调"空"的感觉——回响和混响较大

### 5.3 语音
- 不设全程配音
- 仅在关键剧情处使用少量低语/耳语（听不清内容，营造不安感）

## 六、技术方案

### 6.1 引擎选型
| 引擎 | 优势 | 劣势 |
|------|------|------|
| **Unity**（推荐） | 跨平台成熟、工具链完善、2D支持好 | 包体较大 |
| Godot | 开源轻量、2D原生支持 | 社区资源较少 |
| Cocos Creator | 轻量、H5友好 | 3D能力弱 |

**推荐方案**：Unity 2D + 自研谜题框架

### 6.2 技术架构

```
┌────────────────────────────────────┐
│           Game Manager             │
│  (场景切换、存档、全局状态)         │
├────────────────────────────────────┤
│  Scene Manager  │  Puzzle Manager  │
│  (场景加载/卸载) │  (谜题状态/验证) │
├────────────────────────────────────┤
│  Inventory      │  Dialog/Narrative│
│  (道具/组合)    │  (对话/剧情)     │
├────────────────────────────────────┤
│  Audio Manager  │  UI Manager      │
│  (音效/音乐)    │  (界面管理)      │
└────────────────────────────────────┘
```

### 6.3 关键功能需求
- **存档系统**：自动存档 + 3个手动存档位，支持云存档
- **多语言**：首发中文/英文，预留多语言接口
- **成就系统**：平台原生成就 + 游戏内成就
- **提示系统**：可选的内置提示（有限次数或冷却时间）
- **性能要求**：移动端稳定 30fps，PC端 60fps

### 6.4 数据持久化
- 场景解锁状态
- 道具收集状态（含隐藏道具）
- 谜题完成状态
- 对话/剧情节点标记
- 玩家设置（音量、语言等）

## 七、UI/UX设计

### 7.1 主界面
- 标题画面：大门塘的水墨远景 + 漂浮标题 + [开始] [继续] [设置]
- 设置：音量（主/音效/环境）、语言、画质（移动端）、清除数据

### 7.2 游戏内界面
- **背包栏**：屏幕底部，图标排列，选中高亮
- **道具详情弹窗**：点击背包道具弹出，展示大图 + 描述文字
- **场景切换箭头**：左右侧边缘，半透明，触发热区
- **提示按钮**：右上角，灯泡图标
- **暂停菜单**：[继续] [存档] [加载] [设置] [返回标题]

### 7.3 交互反馈
- 可交互区域：鼠标悬停时高亮/放大/发光
- 道具拾取：道具飞入背包动画
- 谜题解开：短暂震动 + 音效 + 视觉特效（如光晕扩散）
- 场景切换：墨水晕染转场，持续约 0.5 秒

## 十、v0.5 新增内容（2026-05-12）

### 10.1 背包分页系统
- 背包栏位扩展为虚拟无限容量，10 格为一页
- 左右箭头翻页，键盘 1-0 对应当前页格子
- 一次性道具使用后自动删除（船钩、钥匙、符文、令牌、护符、灶神符），不再占据背包

### 10.2 叙事线索链
- 姑母信件改写为「我会去塘底——这是唯一的路」，与后续隐藏真相形成递进
- 祖父日记新增揭示：「初代守门人的誓言中有漏洞。如果封印是守护，为什么需要血来维持？」
- 书房书桌揭示祖父已开始怀疑封印的本质
- 封印之间石台根据是否发现隐藏真相显示不同文本
- 结局根据是否发现隐藏真相增加专属段落

### 10.3 NPC 残影系统
| 场景 | NPC | 出现条件 | 功能 |
|------|-----|----------|------|
| 码头 | 祖父残影 | 捞起钥匙后 | 引导祠堂方向 |
| 祠堂 | 姑母烟雾残影 | 点燃香炉后 | 警告「不要信它」 |
| 书房 | 祖父幻影 | 打开木盒后 | 展示祖父发现真相的犹豫 |
| 卧室 | 姑母残影 | 收集信件后 | 写信场景重现，传递使命 |
| 封印之间 | 守门人集体 | 始终可见 | 质问：下一道锁还是第一把钥匙？ |

### 10.4 道具组合
- 家族合照 + 姑母警告信 = 「隐藏的真相」
- 两张纸边缘撕裂痕迹吻合（曾为同一张纸），夹层浮现隐藏文字
- 揭示：封印不是守护是囚禁，塘底之物是被初代守门人囚禁的河神，姑母不是逃跑而是主动去塘底

### 10.5 文本一致性改进
- 统一阴暗诡谲的文学语调
- 确保每场景文本与整体叙事主线一致
- 道具描述、热点文本、NPC 对话形成交叉引用网络
- 关键信息通过多种渠道重复暗示实现「Aha!」揭示感

## 十一、v0.6 新增内容（2026-05-12）

### 11.1 故事重构：杨梅坑与曾氏三房

- 村中居民全部姓曾，分为**长房、二房、三房**——初代三兄弟曾建国、曾建业、曾建安的后代
- 开场叙事完全重写（5段），融入杨梅坑、三房体系、月圆之夜塘底哭声传说
- 村口（原码头）场景重写：石牌坊、三兄弟刻名浮木、月圆传说暗示
- 祠堂场景重写：三排牌位对应三房、三兄弟木匾、长房守门人传承体系
- 书房场景重写：三房研究手稿、祖父怀疑封印本质的日记

### 11.2 新场景：枫树下

## 十三、v0.8 新增内容（2026-05-12）

### 13.1 新增谜题类型（3种）

**总计7种谜题类型，无重复：**
1. `SlidingPuzzle`（滑动拼图）— 3×3 滑块拼图
2. `CombinationPuzzle`（密码锁）— 数字转轮
3. `SequencePuzzle`（顺序谜题）— 按正确顺序点击
4. `LightPuzzle`（光线反射）— 旋转铜镜、反射光线
5. `PatternPuzzle`（画符阵）— **新增** 3×3 点阵描画图案
6. `MemoryPuzzle`（灵牌配对）— **新增** 翻牌配对记忆
7. `SymbolInputPuzzle`（符文密码）— **新增** 符号按钮输入密码

### 13.2 PatternPuzzle（画符阵）
- 3×3 圆点点阵，玩家按顺序点击圆点画出符阵图案
- 已选圆点显示序号，已连接圆点间绘制金色连线（SVG）
- 点满后自动校验：正确 → 解锁，错误 → 700ms 后重置
- 用于封印之间中央封印：四象归一符阵（水→火→风→土→归一）
- 图案线索来自卧室衣柜 MemoryPuzzle 奖励

### 13.3 MemoryPuzzle（灵牌配对）
- N 对符文配对，每对两个相同符号，随机排列为网格
- 点击翻开，每次最多翻两张：相同 → 保持翻开，不同 → 700ms 后翻回
- 全部配对成功 → 解锁
- 用于卧室雕花衣柜：四元素（水/火/风/土）配对
- 奖励揭示封印之间符阵图案线索

### 13.4 SymbolInputPuzzle（符文密码）
- 一组符号按钮（含 emoji 和文字标签），玩家按顺序点击输入密码
- 输入显示区实时显示已输入符号，支持退格和重置
- 输满后点确认：正确 → 解锁，错误 → 红色闪烁 800ms
- 用于书房抽屉：元素符文（水/火/木/金）密码
- 答案来自祠堂祭祀符文（子·丑·寅·卯 → 水·火·木·金）
